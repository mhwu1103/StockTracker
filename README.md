# 台股成交值排行追蹤器

每天自動抓取上市（證交所）與上櫃（櫃買中心）的收盤行情，算出**成交值前 200 大排行**
並保存歷史，用手機開網址就能看排行、進出榜與個股排名走勢。

排行分成三種範圍，頂部可隨時切換，選過的會記住：

| 範圍 | 內容 |
|---|---|
| 全部 | 上市＋上櫃合併後重新排名（預設） |
| 上市 | 只看證交所 |
| 上櫃 | 只看櫃買中心 |

三種範圍各自計算名次、進出榜與連續進榜天數 —— 同一檔股票在「上櫃」排第 3、
在「全部」可能排第 19，是兩個不同的問題。

沒有伺服器、沒有資料庫：排程跑在 GitHub Actions，資料是 repo 裡的 JSON，
前端是純靜態網頁掛在 GitHub Pages。

## 功能

| 分頁 | 內容 |
|---|---|
| 排行 | 任一交易日的成交值前 200 大，含相對前 1／5／20 日的名次變化箭頭、連續進榜天數、搜尋，並可依官方產業／題材族群／自選股篩選、改排序、設成交值門檻 |
| 站穩 | 新進榜後連續留在榜上的股票：剛滿 N 天（N 可選 2／3／5／10）與連續 N 天以上 |
| 異動 | 新進榜、掉出榜、名次進步／退步最多的前 20 名 |
| 爆量 | 成交量大於門檻（5 千／1 萬／2 萬／5 萬張）且創 N 日新高（20／60／120 日）的股票；第三個條件「收盤價大於開盤價」是可切換的（只看收紅／不限漲跌），關掉就看得到量一樣大但爆量下殺的那一群 |
| 均線 | 5／10／20／60 日線的穿越：近 1／3／5／10 個交易日內剛站上或剛跌破哪一條（最後一欄「不限」是現在就在那一側的全部），四條線 × 五種天數排成矩陣，每格是檔數也是選擇鈕；另可只看「四線全上」「四線全下」，或只看 MACD「已黃金交叉／已死亡交叉」的 |
| MACD | 黃金交叉／死亡交叉：近 1／3／5／10 個交易日內剛交叉的，以及「明天／後天要收在多少才會交叉」的臨界價；另可只看均線「四線全上」或「四線全下」的 |
| 大戶 | 集保股權分散。**大戶從幾張算起可以選**（100／200／400／600／800／1000 張，選過的會記住），整頁的排序與統計跟著門檻走；散戶固定是 100 張以下。本期加碼與減碼最多的各 20 檔、籌碼最集中的 20 檔、股東人數減少最多的 20 檔；每一列除了比例還帶**該門檻有幾個集保帳戶**。點進個股看得到六個門檻並排的變化表、**逐週明細**（比例、pp 與 % 兩種變動、戶數）、三條比例線與股東人數的逐週走勢 |
| 法人 | 三大法人買賣超。主榜是**外資投信同買／同賣**：兩邊<b>各自</b>都買超（或都賣超）門檻以上（0.3／0.5／1／3 億可選，選過的會記住）才進榜，依合計排序。表頭六格是官方的全市場買賣超金額（上市與上櫃各三邊），每一列帶三邊的估算金額與張數、這筆合計佔當日成交值的比重、成交值名次與收盤漲跌 |
| 個股 | 日 K 線（開高低收，疊 5／20／60 日均線）、排名走勢與成交值走勢圖（未進前 300 的日子會斷線）、區間統計與全期間紀錄 |
| 對照 | 自選任兩個交易日並排比較 |
| 大盤 | 大盤與前 200 大的成交值走勢，以及前 200／前 10 大佔大盤的資金集中度 |
| 族群 | 各族群的資金流向：成交值增減（億）、佔榜上比重的位移（pp）與成交值加權漲跌幅，可依三者排序；可展開看該族群當日在榜的個股，分類軸可在「官方產業」與「題材族群」之間切換 |
| 流向 | 同一批數字的兩張圖：**資金地圖**（樹狀圖，面積＝成交值、顏色＝資金增減）與**量價四象限**（橫軸成交值增減、縱軸加權漲跌、泡泡大小成交值、顏色佔比位移） |
| 報價 | 上游產品的公開報價（DRAM／NAND、面板、太陽能、鋰電池材料）與原物料成本（銅、金、銀、鈀、鋁、原油）、大環境（費半、美元台幣），可選五種期間看變化；並把每個族群的**報價中位數**與它在台股的**成交值增減、加權漲跌**擺在同一列對照，點進單一品項還能把報價與該族群成交值疊成一張圖 |

排行、大盤、族群、流向、報價五個分頁的**最上面**有一張「**一句話**」卡片，先把這一頁的重點寫成一句
可以唸出來的話，再讓下面的圖表與清單去印證它。句子裡的數字全部取自那一頁當下真正算出來的
東西——換了日期、換了篩選條件，話就跟著換。其他分頁沒有：它們上面本來就有統計格、下面的清單
也已經排好序，再寫一句只會是把畫面唸一遍。

最新資料距今太久時，頂部會顯示過期提醒，避免把舊資料誤看成當天的盤。

在個股頁可以把股票加入**自選**，榜上會標星號、也能只看自選。自選清單存在瀏覽器的
localStorage，不會上傳，換裝置或清除瀏覽資料就會消失。

涵蓋普通股、特別股與 ETF／ETN，已排除權證、牛熊證等商品。

上市有「當日」與「指定日期」兩支，同一天抓出來完全一致 —— 實測 2026-09-01 的
1,346 檔，成交量與成交值 100% 相同，所以當日排程走輕便的那支、缺漏由歷史那支回補。

**上櫃兩支則對不起來，所以一律走歷史那支。** 櫃買的 openapi
（`tpex_mainboard_quotes`）**只有整股**：它的成交股數永遠是 1,000 的倍數，
盤中零股完全不在裡面。拿 2026-09-02 逐檔比對：

| | 整股（openapi） | 完整（dailyQuotes） |
|---|---|---|
| 3293 鈊象 | 3,850,000 股 · 3,250 筆 | 4,034,186 股 · 10,152 筆 |
| 6640 均華 | 1,280,000 股 · 1,057 筆 | 1,391,072 股 · 6,810 筆 |
| 全市場成交值 | 2,162 億 | **2,285 億** |

差額換算成「每筆幾股」是 19~79 股，正是零股的大小。收盤與開高低兩邊完全相同，
所以只影響成交量與成交值 —— 偏偏那就是本站排行在比的東西，少 5% 不是可以忽略的
誤差。除此之外，來源切換的隔天還會冒出假的爆量訊號（`vh` 拿整股的昨天比完整的今天）。

代價是 `dailyQuotes` 要指定日期、回應大得多（一萬多列、約 1.4 MB），收盤後也要等
久一點才出得來。真的還沒出來就是抓不到，隔天排程的 `backfill.py --days 14` 會補上。

「全部」不需要另外抓：某檔若排得進合併後的前 300 名，它在自己市場裡必然也在前 300 名內，
所以用兩邊各自的前 300 名就能還原出正確的合併排行，由 `build_history.py` 算出來。

族群頁有兩種分類軸，並存而不是二選一：

- **官方產業**（`industry.json`）採證交所的官方分類，由 `fetch_industry.py` 自動更新，
  一檔只屬一類、永遠不會漏掉任何一檔，但與市場口中的題材族群對不起來。
- **題材族群**（`themes.json`）是人工維護的供應鏈視角（AI 伺服器、光通訊、CCL、
  被動元件、重電、功率元件…），分大族群與子族群兩層。一檔可以同時屬於多個族群，
  所以各族群的佔比加總會超過 100%；分母一律取榜上成交值總額，每檔只算一次。
  名單外的個股歸「未分類」並固定排在最後，ETF 依 `industryOf()` 自動成一族，
  新掛牌的 ETF 不必手動補。歸類依據是公開資訊觀測站的「主要經營業務」與公司營收比重，
  不是股名或官方產業別。最新交易日的三種範圍幾乎全覆蓋（上櫃剩 3 檔性質太雜的刻意不歸）；
  回看較早的日期時仍會出現「未分類」，485 天裡曾上榜但不在名單上的還有 582 檔。

兩份對照都取自最新一次的結果，並回頭套用到歷史日期。

族群頁上的三個數字要一起看：

- **成交值增減（億）** 是直覺的「錢變多還變少」，但大盤整體縮量時所有族群都會是負的。
- **佔比位移（pp）** 把大盤的縮放抽掉，看的是錢實際上從哪一族轉到哪一族。
  兩者方向相反是常態：整體縮量 13% 的日子裡，只縮 8% 的族群成交值是負的、佔比卻在上升。
- **成交值加權漲跌幅** 補的是方向。成交值是買賣雙邊的總量、本身沒有方向，
  「爆量」可能是搶進也可能是倒貨，配上加權漲跌幅才知道這些錢把價格推上去還是砍下來。

基準日在榜、當日整族退出前 200 大的族群會以「整族退出前 200 大」單獨列出——
那是實實在在的資金流出，不能因為今天榜上沒有就當作沒發生。

## 報價

報價是因，成交值與股價是果，但兩者不會同步。報價頁收的是**能自動抓、可公開瀏覽**
的上游報價，並且一律把它擺在對應族群旁邊看。

**被動元件與功率元件沒有公開的成品報價。** MLCC、晶片電阻、MOSFET、IGBT、SiC 的
報價握在付費通路與研究機構手上，沒有可自動抓的公開頁。這一頁能給的只有它們的
上游原料價 —— 銅、銀、鈀（MLCC 的內外電極金屬）與多晶矽 —— 在畫面上標成
「成本」而不是「報價」。原料漲不等於成品漲得動，漲價轉不轉嫁得出去是另一件事，
這一頁不回答那個問題。CCL 與 ABF 載板同理，只有銅與金這兩個成本指標。

**歷史是自己累積的。** TrendForce 的免費頁只顯示最新一筆，走勢圖在會員區，所以
每天抓一份快照存起來，序列的起點就是開始追蹤的那一天。`backfill_quotes.py` 可以
從網頁典藏館（Wayback Machine）把同一批頁面過去的樣子抓回來解析 —— 解法與現抓
完全相同，但典藏頻率大約**一個月一份**，所以那段歷史是稀疏的。現貨價因此只看得出
大趨勢；合約價與鋰電池材料本來就是半月或一個月更新一次，稀疏幾乎不損失資訊。

**點距不等寬是報價自己的節奏。** 序列的橫軸是每張表自己的 Last Update，同一個
報價日只留一個點 —— 一筆月更的合約價天天抓也不會被畫成 30 個一樣高的點。
所以現貨一天一點、合約一個月一點，圖上點距不等，那不是資料缺漏。

**各期間漲跌要有下限。** 「近一月」的基準取「最新報價日往回推 30 個日曆日」附近
那一筆，而且只接受落在 30～60 天前的點。少了這個下限，歷史稀疏的品類會拿一年前
那一筆去比 —— 算出來的數字是真的，標籤卻是假的。湊不出基準就顯示「—」，不硬給。

**回補會撈到停止報價的舊品項。** TrendForce 換過規格、下架過品項，那些序列有價值
但不能混在今天的清單裡。判準是每張表自己的最新報價日：那一天的表上找不到它，
它就是停更的，單獨列在「已停止報價」並排除在漲跌統計之外。

**來源網站自己也會打錯字。** 2025-03-12 的「N型致密料」高點 42、低點 37、均價 4.00
—— 照抄下去圖上就是一次 −90% 的暴跌。快照保留抓到的原始數字（那是紀錄），
序列這一端要求均價落在高低點之間（留 5% 餘裕），不合的那一格丟掉並印出來。

**報價 × 族群那三個數字。** 左邊是該族群所有對應品項的報價**中位數**（不用平均：
同一族裡 DDR5 與 DDR3 的漲幅可以差一個數量級，平均會被單一品項帶著跑）。右邊是
這一族在台股的反應：成交值增減（億）、當日成交值、成交值加權漲跌幅。
增減用金額不用百分比 —— 成交值只含當天排進前 300 名的成分股，基準日在榜檔數不同時
百分比會被「進榜」本身放大成幾千 %。兩邊的期間也對不齊：報價按日曆日算、
成交值按交易日算，而報價本身不是每個交易日都會更新，畫面上都標了出來。

單一品項頁的第二張圖把報價與族群成交值疊在一起，兩條線都換算成「以區間首日為 100」
的指數 —— 一邊是美元／顆、一邊是億元，共用一個縱軸只會讓其中一條貼著軸變成直線。
報價在下一次更新之前維持不變，所以畫成水平段。

「流向」分頁把同一批數字畫成圖：**資金地圖**用面積看錢在哪裡、用顏色看往哪個方向動
（顏色吃的是增減「幅度」不是金額，小族群翻倍才不會被半導體那種量體洗掉）；
**量價四象限**把量與價拆成兩軸，右上角是量價齊揚的資金進駐、右下角是爆量下殺的出貨——
兩者的成交值都在放大，方向卻相反，這就是成交值不能當成買盤看的原因。
兩張圖都是純 DOM／SVG，不依賴 Chart.js，離線時也看得到。
地圖上每一塊的字級是量了實際大小之後算出來的，塞得下多大就用多大，長名字會折兩行；
真的塞不下就只留 `title` 的提示。這也是全站唯一有桌機版型的地方——塊夠不夠大看的是面積，
手機寬度窄，得靠高度把面積補回來，所以手機的地圖是直的、桌機是寬的；
寬螢幕（≥ 900px）下這一頁還會滿版，不像其他分頁限在 720px。

均線分頁看的是「剛穿越」而不是「現在站在哪」：正數是已連續站上幾個交易日
（1 就是今天剛站上），負數是已跌破幾天，所以「近 3 日站上」等於連續站上 1～3 天。
收盤價剛好等於均線算在跌破那一側。矩陣最後一欄「不限」不看天數，列的是現在就收在那一側的全部。

「四線全上／全下」是另一個維度：四條均線各自的位置（收盤價高於／低於該線）全部同向才算，
有一條算不出來就不算數。它與矩陣是 AND 關係——選了「四線全上」再按「近 1 日站上 5 日線」，
看到的就是今天剛站回 5 日線、而且四條線全在腳下的那幾檔。

**均線與 MACD 可以交叉著篩。** 同一檔的 `ma`／`mav`／`macd` 本來就在同一份 daily 檔裡，
兩頁也是從同一個「榜上前 200 名」出發，所以兩邊各自借對方一個篩子：均線頁多一排
「已黃金交叉／已死亡交叉」，MACD 頁多一排「四線全上／全下」。借的都是對方的**現在站在哪一側**，
不是第二套天數——一頁只留一個「近 N 日」，才不會冒出「近 3 日站上」配「近 5 日交叉」
這種要想很久的組合。篩子與矩陣（MACD 頁是時點那排）的計數一起連動，
所以「近 3 日剛站上 20 日線」＋「已黃金交叉」＝ 價格剛翻上均線、動能也還在交叉後那一側的那一群。
兩邊對邊界的處理本來就一致（收盤價等於均線算跌破、柱等於 0 算死亡交叉），交集不會有灰色地帶。
代價是命中數掉得快，而且 MACD 要 60 個連續交易日、比 60 日線還嚴，一選 MACD 篩選就會少一批。

均線頁那排寫「已黃金交叉」而不是「柱在零軸上」，是因為 MACD 圖上有兩條線都能叫零軸：
**柱**的零軸（DIF 在不在 DEA 之上）和 **DIF** 的零軸（12 日 EMA 在不在 26 日 EMA 之上）。
篩的一直是前者，但兩者常被混為一談——柱翻正只代表短期動能追過了自己的均值，
DIF 仍可能是負的（實測榜上經常有幾十檔是柱正、DIF 負）。
「已」字則是在說這是狀態不是事件：交叉可能是今天，也可能是二十天前，
要找剛發生的那幾檔得回 MACD 頁按「近 N 日」。

均線要**連續**的收盤價才算得準，而 `daily/` 只留前 300 名——一檔只要有幾天掉出前 300，
那段就是空的（實測榜上前 200 名裡，60 日線只有約一半湊得齊）。所以抓取時另外存一份
`close/` 全市場收盤價，均線由 `build_history.py` 算完寫進 daily 的 `ma`／`mav`，
前端不必為了 60 日線去抓 60 個檔案。收盤價一斷（停牌、剛上市、回補還沒補到那麼早）
就標「資料不足」，不硬算；往回數天數時若是資料先斷而不是真的穿越，天數小於 11 天的
一律當成資料不足，免得「有資料的這 3 天都站上」被報成「3 天前剛站上」。
收盤價沒有還原權值，除權息當天的跳空可能被當成跌破。

個股頁的**日 K 線**吃的是同一份 `close/`，只是多用了開、高、低三個價。
Chart.js 沒有 K 線圖型，畫法是兩組浮動長條疊起來：細的畫 [最低, 最高] 是影線、
粗的畫 [開盤, 收盤] 是實體，紅漲綠跌。開盤等於收盤的十字線實體高度是 0、長條會整根消失，
所以補一個隨價格區間縮放的最小厚度，讓它至少還是一條看得見的橫線。
圖上三條均線（5／20／60 日）是拿這張圖自己的收盤價現算的，不是讀 daily 裡那份——
那份只有前 200 名才有，掉出榜的日子就會斷。為了讓 60 日線一進畫面就有值，
資料會多抓三個月當暖身，算完再切回要顯示的區間。

**K 線檔為什麼切到「一檔一個月」。** K 線是逐日資料的轉置，轉置過的檔案每天都得整個重寫，
切得愈粗每天重寫的量就愈大——切成一年一檔的話每天要重寫十幾 MB，一年就把倉庫撐爆。
切到月：只有當月那批會變，前面的月份寫完就凍住；前端要 120 個交易日也才抓 6～7 個小檔
（每檔約 1 KB），而且過去的月份內容永不改變，快取可以一直留著。
只有曾經進過該市場前 300 名的個股才出檔，那也正是前端唯一走得到個股頁的那些代號。

高低價是加 K 線時才開始收的，在那之前抓的日子只有收盤價。缺開盤就沿用前一天的收盤、
缺高低就取開收的極值——畫得出來但沒有影線，不會假造出當天其實沒有的振幅。
要把舊日子補齊得用 `python scripts/backfill.py --from YYYY-MM-DD --force` 整段重抓。

MACD 分頁除了「已經交叉」，還算得出**明天要收在多少才會交叉**。這不是預測，是解方程式：
三條 EMA 都是「舊值 × 常數 ＋ 新收盤價 × 常數」，所以「明天的柱等於 0」是一條一元一次方程式，
臨界價直接寫得出來。負的百分比代表連平盤或下跌都會交叉，那是最接近成真的一群。
「後天」多一個假設 —— 明天以平盤計，兩天有兩個未知數，不假設一個就解不出來；
兩邊都只列漲跌停 ±10% 走得到的。

daily 檔裡存的是三條 EMA 而不是 DIF／DEA／柱，就是為了讓前端推得出那條臨界價。
EMA 沒有真正的起點，是從第一天的收盤價一路遞推的，所以連續收盤價少於 60 個交易日就不出 MACD
（26 日 EMA 的起點誤差到那時只剩約 1%），寧可空著也不給一個還帶著起點味道的值。

`docs/data/history/`、`index.json` 與 daily 檔裡的連續進榜欄位都是衍生資料，
`build_history.py` 每次都由 `daily/` 從頭重算，只有內容真的改變的檔案才會重寫。

連續進榜天數以「成交值前 200 名」為準。若某段連續紀錄一路連到本站最早的日期
（目前是 2024-08-16），前端會顯示成 `連 484+ 天`，表示實際天數可能更長。

## 大戶

集保結算所每週五結算一次，把每一檔的股東依持股張數分成 15 級並整份公開。
這一頁只問一件事：**這一段時間，籌碼是往大戶那邊集中，還是散到散戶手上**。

**大戶從幾張算起是選出來的。** 市場上 400 張與 1,000 張兩種說法都有人用，看的東西
也不一樣：400 張以上還含著不少中實戶，1,000 張以上幾乎只剩法人、公司派與保管銀行。
同一檔在 400 張那一層加碼、在 1,000 張那一層卻在減碼，代表籌碼是從最大的手上流到
次大的手上 —— 那是換手不是出貨，只看一個門檻會把兩者混為一談。個股頁把六個門檻
並排列出來就是為了看這件事。

門檻只能從官方的級距裡挑，中間的數字（例如 500 張）官方沒有分，硬給只會是假的精確：

| 門檻 | 官方分級 |
|---|---|
| 100 張以上 | 第 10～15 級 |
| 200 張以上 | 第 11～15 級 |
| 400 張以上（預設） | 第 12～15 級 |
| 600 張以上 | 第 13～15 級 |
| 800 張以上 | 第 14～15 級 |
| 1,000 張以上（千張大戶） | 第 15 級 |

**散戶固定是 100 張以下（第 1～9 級），不跟著門檻走。** 兩邊都會動的話，比較的基準
就變成兩件事在動，看不出到底是誰交給了誰。門檻選在 100 張時兩者正好互補。

快照存的是**累積級距梯** `cum1..cum15`（第 N 級含以上的比例），所以任何門檻都是直接
查表、單一級距是相鄰兩項相減 —— 官方那張表在「比例」這個維度上的解析度全都留著了，
以後想看哪個門檻都不必重抓一次。散戶是 `cum1 − cum10`，不是 `100 − cum10`：
`cum1` 已經排除了不屬於任何級距的「差異數調整」，拿 100 去減會把它算到散戶頭上。

**比例會被「跨門檻」騙，所以還要存戶數。** 級距是門檻不是連續的尺：一個原本持有
900 張的帳戶買到 1,100 張，他整個部位會從 400~1000 張那一層一次跳到千張那一層 ——
比例搬動一大塊，戶數卻只多一個。小型股上這是常態，一檔七萬張的股票，一個千張帳戶
就佔 1.3 個百分點。所以 `p10..p15` 記著大戶那六層各有幾個集保帳戶（對齊門檻選單的
六個張數，散戶戶數是合計減 `p10`），畫面上比例旁邊一定同時列出戶數。

真實的例子：8103 瀚荃 2026-08-21 → 08-28 的千張大戶從 24.22% 跳到 32.16%（+7.94pp），
看起來像有人大買 6,228 張；但戶數是 7 戶變 11 戶，而同期 400~1000 張那一層少了 2 戶。
拆開來是「2 戶跨過千張、2 戶新建大部位」，不是「一週買進六千張」。少了戶數這一欄，
這兩件事在畫面上長得一模一樣。

**變動有兩種寫法，個股頁的逐週明細兩個都給，但單位不同。** `pp` 是「佔集保庫存的
比例」差了幾個百分點（24.22% → 32.16% 就是 +7.94pp）；旁邊的 `%` 講的是**張數**
多了或少了幾成，不是「比例的相對變化」。

刻意不用「比例的相對變化」，是因為那個數字有兩個毛病。一是它跟比例本身長得一樣：
`32.16%` 與 `+32.8%` 並排，兩個都是 `%` 卻是完全不同的東西，一定會被讀錯。
二是比例的**分母自己會變**：8103 的集保庫存從 92,278 張減到 78,437 張那一段，
千張大戶的比例上升 1.95pp、實際張數卻少了 2,272 張（−9.0%）——
拿比例算相對變化會說出「成長 7.1%」，跟事實相反。換成張數就沒有這個問題，
畫面上那一列現在是紅色的 `+1.95pp` 配綠色的 `張數 -9.0%`，矛盾直接看得見。

張數是比例乘上集保庫存換算的，比例只留兩位小數，所以尾數有幾張的誤差，
看的是量級不是精確值。榜上排序與跨個股比較一律用 pp —— pp 可以相加
（四層的變化加起來正好是 0），張數則因為股本大小差太多而不能直接比。

比例一律由「股數 ÷ 合計股數」現算，不是把官方那欄四捨五入到小數點後兩位的百分比
加起來 —— 每一級各差 0.005、累加十幾級就差到 0.05 個百分點，而這一頁在看的週變化
本來就常常只有 0.1 個百分點。

**這些數字不等於「主力」。** 集保分的是**帳戶**不是實質股東：外資的持股掛在保管
銀行底下，一家保管銀行就是一個千張大戶；公司派、董監與庫藏股同樣落在大戶級距。
台積電的千張大戶常年在八成以上，那是外資與國發基金，不是有人在偷偷吃貨。
分母是集保庫存數，未集保的實體股票不在裡面。而且這是一週一次的**存量**快照，
看得出集中度往哪邊移動，看不出是誰買的、什麼價位買的。

「大戶加碼」與「股東人數減少」是同一件事的兩面：股數沒有變、持有的人變少，就是
有人把零股賣給了大戶。兩張榜重疊的那幾檔，是這段期間籌碼收得最乾淨的。反過來，
股東人數暴增配上大戶比例下降就是散戶在接手 —— 台積電從 2024 年初的 106 萬股東
變成 2026 年 8 月的 305 萬，就是這樣一路稀釋掉的。

**歷史是自己累積與回補的。** 那個 CSV 只給最新一週，下一週就被蓋掉，帶 `date`
參數也沒用（回來的位元組數一字不差）。所以每週抓一份存起來，另外有兩條路往前補，
補出來的形狀完全不同：

| `--source` | 範圍 | 密度 | 成本 |
|---|---|---|---|
| `wayback` | 全市場 | 一年兩三份 | 每份一個請求 |
| `stock` | 補抓時指定的那一批 | 近一年、真正的每一週 | 週數 × 檔數 個請求 |

`stock` 走的是集保官網的個股查詢頁，下拉選單留著近一年的週資料日 —— 那是唯一
補得到「上週」的地方。代價是它一次只給「一檔 × 一週」，13 週 × 200 檔就是 2,600 次
請求（約半小時）。目前補的是**近 13 週 × 最新交易日的成交值前 200 名**。
CSRF token 是一次性的，但回應頁裡就帶著下一個，接力用即可，不必每查一檔先開一次表單。

那一頁的「序」欄只是**列號**不是級距編號：有「差異數調整」那一列的股票，合計排在
第 17 列；沒有的（例如 2454）排在第 16 列。所以解析認的是級距文字的下界，不是序號。
兩條路解出來的數字對得起來 —— 拿同一週的十檔交叉比對過，與官方 CSV 完全一致。

**部分涵蓋的那幾週要標出來。** 逐檔補的那幾週只有被補的那一批股票，典藏館那邊
則因為 1 MB 的抓取上限（原始檔 2.3 MB）有兩份是被從中間切斷的（2024-02-23 與
2025-01-10，代號大約 5300 以後沒有）。這些快照都標成 `partial` 並附上 `why`，
畫面照著講 —— 那幾週查不到的股票是沒補到，不是退出了集保。

**各期間的變化都有下限。** 「較前一週」只接受落在 4～21 天前的那一份，湊不出來就
顯示「—」，不拿半年前那一筆去充當上週。往前回補的那一段稀疏，短期比較本來就湊不出
基準；每週排程累積下去之後，愈近的日期會愈完整。

## 法人

三大法人的買賣超日報，主榜只問一件事：**外資與投信有沒有站在同一邊**。

兩者的錢性質不同，所以「同買」才有意思。外資動的是全球資金的配置，一天幾百億、
常常是被動的（ETF 調整成分、指數換股、避險部位），對個別公司的看法不見得在裡面。
投信動的是國內主動型基金，一檔幾千萬到幾億，經理人得對每一筆負責。兩邊的理由本來
各自獨立，同一天在同一檔上同向，才代表兩種完全不同的決策流程指到了同一個地方。

所以這一頁**不做「外資買超排行」**：那張榜前幾名幾乎天天是同一批權值股，看久了
沒有資訊；只有一邊在動也很難解讀（外資買超十億可能只是某檔 ETF 在建倉，
投信賣超三億可能只是基金在應付贖回）。

**門檻是「兩邊各自」都要達到，不是合計。** 合計那樣算的話，外資買超十億配上投信
賣超九億也會進榜，方向卻是相反的。門檻可選 0.3／0.5／1／3 億，預設 0.5 億 ——
那是市場上最常用的說法，也差不多是「投信一檔基金認真布局」的量級。

### 金額是估算的，合計不是

這是這一頁最重要的一件事：**官方的個股資料從頭到尾只有股數，沒有金額。**
證交所的 T86 與櫃買的 dailyTrade 每一欄都是「買進股數／賣出股數／買賣超股數」，
金額只出到全市場的彙總表，沒有分到個股。所以個股的金額一律是

    買賣超金額（估）＝ 買賣超股數 × 當日收盤價

真正的成交均價不等於收盤價。拿全市場合計去對官方那張買賣金額彙總表（22 個交易日、
上市與上櫃分開算）：外資的相對誤差中位數約 5%、金額差距中位數 2.8 億、最大 37 億。
量級與方向是可靠的，但**門檻邊緣的個股會因為這幾個百分點進出榜**。

所以每一天的檔案裡兩種都存：`total` 是官方彙總表的精確金額、`est` 是同一天把個股
估算值加總起來的結果。畫面上最顯眼的那六格（上市與上櫃 × 三邊）取的是 `total`，
不是估算 —— 表頭的數字要能跟新聞上的「外資今天賣超幾百億」對得起來。

### 欄位位置用「數字之間的關係」驗

兩支來源的欄位順序都沒有版號，讀錯不會報錯、只會把投信的數字寫到自營商欄上 ——
那是安靜的錯誤答案，比整個掛掉還糟。所以抓回來先驗一次：

- 上市的 T86 有欄名，逐欄比對關鍵字；再驗「四段相加 = 官方的三大法人合計欄」。
- 上櫃那張表的 24 欄裡，除了前兩欄以外**全叫**「買進股數／賣出股數／買賣超股數」，
  欄名認不出誰是誰。改驗數字的關係：每一組的買 − 賣 = 買賣超、合計組 = 兩個子組相加、
  最後一欄 = 三邊相加。順序真的被改動時這些等式會一起垮掉。

驗不過就整天不寫檔，寧可缺一天也不要存一份對不起來的。

### 其他口徑與邊界

- **「外資」含外資自營商**（外陸資 + 外資自營商），「自營商」含自行買賣與避險，
  與市場上引用的口徑一致。
- **兩個市場只有一邊有資料時整天不寫。** 只寫一半的檔案沒有人看得出來，
  少掉的那個市場會被讀成「那邊的法人整天沒動」。櫃買出得比證交所晚，
  隔天排程的 `--days 14` 會把這一天補上。
- **三邊的估算金額都不到 0.05 億（500 萬元）的不存。** 全市場一天有兩千多檔沾到
  法人的買賣，一大半是幾百股的零頭（法人的零股交易、ETF 實物申贖的尾數）；
  存下來一天要 90 KB，濾掉之後 43 KB，而丟掉的那些在任何法人分析上都不是訊號。
  門檻本身寫進檔案的 `cut` 欄位，讀的人才知道這份資料的邊界在哪。
- **當天完全沒成交卻有法人異動的不收**（暫停交易、全額交割股沒人買，多半是盤後
  鉅額或錯帳更正）—— 沒有收盤價就沒有金額。檔案裡用 `noPrice` 記下有幾檔。
- 每一列的金額底下擺的是「**佔成交值**」＝外資與投信合計 ÷ 當日成交值。
  同一個門檻套在大小型股上意義完全不同：0.5 億對一檔日成交 200 億的權值股是零頭，
  對一檔日成交 3 億的中小型股是當天成交值的六分之一。成交值只有前 300 名有
  （本站的每日檔就留到那裡），其餘的那一格留白。

### 這些數字不能拿來講什麼

買超不等於看多：外資的買超裡混著避險、借券還券與指數調整，投信在季底與年底有作帳
的動機。而且淨額看不出成本 —— 同樣買超一億，開盤搶進與收盤前掛低接的處境完全不同，
日報表只有一個淨數字，分不出來。**這是籌碼的事後紀錄，不是投資建議。**

## 本機使用

```bash
pip install -r requirements.txt
python scripts/fetch_daily.py        # 抓最新一個交易日
python scripts/fetch_industry.py     # 抓產業別對照（偶爾跑一次就好）
python scripts/build_history.py      # 重建索引與歷史
python scripts/fetch_quotes.py       # 抓上游報價與原物料（選用）
python scripts/build_quotes.py       # 重建報價目錄與序列
python scripts/fetch_institutions.py # 抓三大法人買賣超（選用）
python scripts/build_institutions.py # 重建法人目錄
python scripts/fetch_holders.py      # 抓當週集保股權分散表（選用）
python scripts/build_holders.py      # 重建集保目錄與個股序列
cd docs && python -m http.server 8765
```

瀏覽器開 <http://localhost:8765>。

回補更多歷史（每次請求間隔 4 秒以免被證交所限流，兩年約需 35 分鐘）：

```bash
python scripts/backfill.py --from 2024-08-16 --to 2026-08-14
python scripts/build_history.py
```

上櫃的歷史 API 每次回應約 1.4 MB，比上市慢得多，兩年份大約要一小時。
只補單一市場可以用 `--scope twse` 或 `--scope tpex`。

回補報價歷史（從網頁典藏館抓，約 60 份典藏、每份間隔 3 秒，十分鐘內跑完）：

```bash
python scripts/backfill_quotes.py --dry-run     # 先看有哪些典藏
python scripts/backfill_quotes.py --since 2025-01-01
python scripts/build_quotes.py
```

`--cat dram` 可以只補單一品類，`--limit 5` 只抓最新的幾份。
典藏站偶爾會拒連或逾時，跳過的那幾份下次再跑就會補上（已經有的不會重抓）。

回補法人歷史。兩支來源都能指定任一交易日，所以直接往前補幾天就好
（一天四個請求，30 天約兩分鐘）：

```bash
python scripts/fetch_institutions.py --days 30
python scripts/build_institutions.py
```

已經有檔案的日期會自動跳過，要重抓加 `--force`；只看不寫加 `--dry-run`。
金額要靠 `docs/data/close/` 的當日收盤價，那一天的行情還沒抓的話它會自己現抓一次。

回補集保歷史。典藏館這條是全市場但很稀疏，幾分鐘就跑完：

```bash
python scripts/backfill_holders.py --dry-run
python scripts/backfill_holders.py --since 2024-01-01
```

逐檔那條補得到近一年的每一週，但一次只有一檔，跑之前先用 `--dry-run` 看要打幾次：

```bash
python scripts/backfill_holders.py --source stock --dry-run
python scripts/backfill_holders.py --source stock --weeks 13 --top 200
python scripts/backfill_holders.py --source stock --codes 2330,2454
python scripts/build_holders.py
```

中斷了不會白跑：已經補進快照的（代號 × 週）下次會自動跳過，而且每 50 檔就寫一次盤。

## 部署到 GitHub Pages

1. 把整個目錄推上 GitHub。
2. Settings → Pages → Source 選 **`GitHub Actions`**（不是 `Deploy from a branch`）。
   排程流程會自己把 `docs/` 發佈出去；走分支部署的話，機器人的 push 不會觸發
   Pages 重新建置，網站會停在舊資料。
3. Settings → Actions → General → Workflow permissions 選 `Read and write permissions`
   （排程需要把資料 commit 回 repo）。
4. Actions 分頁手動跑一次「每日更新成交值排行」確認流程正常。

每天的資料是由 GitHub 配發的臨時虛擬機提交的，作者顯示為 `github-actions[bot]`，
用的是每次執行自動產生、結束即失效的 `GITHUB_TOKEN`，你不需要設定任何金鑰。

之後每個交易日台灣時間 16:30 左右會自動更新。

## Telegram 每日推播（選用）

每個交易日收盤後推播當日新進榜、以及連續進榜 2／3／5 天的清單。
沒有設定金鑰時這一步會自動略過，不影響其他流程。

設了 `WATCHLIST` secret（逗號分隔的代號，例如 `2330,2454`）之後，改成只推這幾檔的
進出榜動態；當天完全沒動靜就不發，避免每天一封「今天沒事」讓人乾脆關掉通知。
網站上的自選股存在瀏覽器裡**不會**自動同步過來 —— 排行頁選「只看自選」時會列出
可以直接複製的代號字串，貼進 secret 即可。

1. Telegram 找 **@BotFather** → `/newbot` → 取得 bot token。
2. 對你的新 bot 隨便說一句話，然後開
   `https://api.telegram.org/bot<TOKEN>/getUpdates`，找 `"chat":{"id":...}` 就是你的 chat id。
3. GitHub repo → Settings → Secrets and variables → Actions → New repository secret，
   分別新增 `TELEGRAM_BOT_TOKEN` 與 `TELEGRAM_CHAT_ID`。

**金鑰只放在 GitHub secret，不要寫進程式碼或 commit。** 程式從環境變數讀取，
不會出現在原始碼或執行紀錄裡。

先在本機預覽訊息長什麼樣（不需要金鑰、不會發送）：

```bash
python scripts/notify_telegram.py --dry-run
```

要調整推播哪幾種連續天數，改 `notify_telegram.py` 最上面的 `STREAK_GROUPS`。
要預覽自選股版本的訊息：

```bash
python scripts/notify_telegram.py --watchlist 2330,2454 --dry-run
```
